# 업로드 저장

글 사진과 프로필 이미지는 로컬 디스크에 저장한다. 외부 객체 저장소는 아직 연결하지 않았다.

## 로컬 개발

- 저장 폴더: `apps/api/uploads/` (기본). `UPLOAD_DIR`이 있으면 그 경로를 쓴다.
- 이 폴더는 git에 올리지 않는다.
- 조회 주소: `GET /api/files/:id` (로그인 없이 볼 수 있다. 숨긴 글의 이미지도 id를 알면 받을 수 있으므로, 운영에서는 비공개 글 접근 제한을 추가로 두는 것이 좋다.)
- 업로드: `POST /api/uploads` (로그인). `kind=avatar`이면 프로필 이미지.

## 제한

- 형식: JPEG, PNG, WebP, GIF. 확장자가 아니라 파일 앞부분(매직 바이트)으로 검사한다.
- 파일당 최대 5MB.
- 글 하나당 이미지 최대 10장. 관련 팀은 5개까지.
- 응원팀은 회원당 10개까지, 대표 응원팀 1개.

## 첨부파일 수명

- 글 작성 중 올린 이미지는 `post_id`가 비어 있다. 글을 등록할 때 `imageIds` 순서대로 붙인다.
- 글 수정에서 `imageIds`에 없는 기존 이미지는 파일과 DB 행을 지운다.
- 글 삭제(작성자·관리자) 때 그 글의 이미지를 지운다.
- 작성 취소로 글에 붙지 못한 이미지는 24시간이 지나면 다음 업로드 때 같은 회원의 고아 파일을 지운다.
- 프로필 이미지를 바꾸면 이전 파일을 지운다.

## 운영에서 영구 저장할 때

배포 서버의 로컬 디스크는 재시작·스케일 아웃 때 사라질 수 있다. 운영 전환 시 필요한 것:

1. `UPLOAD_DIR`을 영구 볼륨으로 두거나
2. `UploadsService`의 저장·조회만 S3 호환 저장소로 바꾸고
3. `GET /api/files/:id`는 저장소 URL로 리다이렉트하거나 프록시한다.

결제나 클라우드 계정 연결은 이 작업에서 하지 않았다.
