# 공통 검색·필터 기준

이 저장소: 화면 예외·버튼 문구(검색)·다크 테마는 `PAGES.md`가 이 문서보다 앞선다. PREVIEW.html 색은 쓰지 않는다.

버전: 1.2.0 · 우선순위: 최신 사용자 요청 → 화면별 명세 → 공통 기본값

이 표준은 검색·필터·목록·정렬·기간 조회 작업에 사용한다. 사용 중인 화면과 데이터에 맞게 적용하고, 관계없는 화면을 자동 개편하지 않는다. 화면별 원천·선택·예외는 같은 폴더의 PAGES.md, 필요한 상세 기준은 DETAILS.md에 둔다.

## 1. 기본 화면

    상태 [전체 ▾]  권한 [전체 ▾]  기간 [오늘 ▾]
    가입일 · 시작 [YYYY-MM-DD] ~ 종료 [YYYY-MM-DD]  검색 [통합 검색어  ×] [조회] [초기화]
    적용 조건: [상태: 활성 ×] [글 수: 10 이상 ×]       [상세 조건 1]

- 공간이 충분한 PC에서는 기본 입력을 한 행에 놓는다. 좁아지면 그룹 단위로 줄을 바꾸고 날짜 시작·종료는 나란히 유지한다.
- 패널: 흰 배경, 테두리 1px, 모서리 약 9px, 안쪽 여백 10px 12px, 항목 간격 약 8px.
- PC 입력·선택·버튼 높이는 34px, 글자는 13~14px, 입력 모서리는 약 7px. 모바일 조작 영역은 더 넓힌다.
- 각 입력에 보이는 라벨을 연결한다. 검색은 '검색', 날짜 그룹에는 '가입일' 같은 기준과 '시작/종료'를 표시한다.
- 조회는 강조 버튼, 초기화는 보조 버튼. 결과 수·조회 기준·적용 조건은 패널 아래에 표시한다.
- 통합검색 하나로 허용된 문자·식별 필드를 찾는다. 제목/내용/작성자 같은 검색대상 선택과 게시판 카테고리 드롭다운을 기본으로 추가하지 않는다.
- 상태·권한·유형처럼 실제 업무에 필요한 선택칸은 유지한다. 긴 선택지는 검색 가능한 선택 UI를 쓴다.
- 자주 쓰는 조건만 기본 영역에 두고 나머지는 상세 조건으로 묶는다. 다운로드·엑셀·CSV·PDF 내보내기·인쇄는 별도 요청이 있을 때만 검토한다.
- 기존 테마 토큰을 우선한다. 신규 기본 예시: 배경 #f5f6f8, 입력 테두리 #8a93a1, 글자 #1a212b, 보조 글자 #5b6472, 강조 #1b5bd7.

## 2. 기본값과 날짜

- 날짜로 조회하는 모든 목록은 프로젝트 시간대(기본 Asia/Seoul)의 오늘이 기본이다. 시작·종료 입력과 첫 API 요청을 같게 한다.
- 문의·신고 대기열도 자동으로 전체기간으로 바꾸지 않는다. 전체기간 미처리 조회가 필요하면 명시적인 바로조회로 제공한다. 기본값 변경은 사용자 요청이나 기존에 확정된 화면 정책을 PAGES.md에 기록한 경우에 적용한다.
- 설정·참조 옵션·수신자 선택처럼 날짜 조회가 주목적이 아닌 화면은 날짜 필터를 억지로 만들지 않고 적용 제외 이유를 명세한다.
- 기간은 오늘/어제/최근 7일/최근 30일/이번 주/이번 달/전체기간/직접 지정. 이번 주는 월요일~오늘, 최근 N일은 오늘 포함 N개 날짜다.
- 날짜 기준을 명확히 하고 서버에서 시작일 00:00 이상, 종료일 다음 날 00:00 미만으로 조회한다.
- 실제 달력에 존재하는 날짜인지 검증한다. 형식 검사나 Date 생성 성공만으로 유효하다고 판단하지 않는다.
- 상대 기간은 명시적으로 조회할 때 현재 날짜로 계산하고 입력·요청·결과를 일치시킨다. 직접 지정한 날짜는 고정한다. 입력 중인 값을 자정에 몰래 덮어쓰지 않는다.
- 전체기간은 명시적인 모드다. 빈 날짜·입력 오류·결과 0건을 전체기간으로 바꾸지 않는다. 초기화는 오늘과 화면 기본 조건으로 돌아간다.

## 3. 검색과 적용 시점

- 검색어는 앞뒤 공백을 정리한다. 기본 연산은 단어 사이 AND, 각 단어의 검색 대상 필드 사이 OR, 서로 다른 업무 조건 사이 AND다. 같은 조건의 복수 선택은 OR다.
- 식별 번호는 정확 일치를 지원한다. 대소문자·부분 일치·특수문자·길이 제한·IME 동작을 UI와 API에서 맞춘다.
- 초안과 적용 조건을 구분한다. 조회 또는 Enter로 초안 전체를 한 번에 적용하고 1페이지로 이동한다.
- 검색창의 ×는 검색어 초안만 지운다. 바로 서버에 적용하지 않는다. 전체 초기화는 모든 초안을 기본값으로 바꿔 즉시 조회한다.
- 적용 조건 칩의 ×는 해당 적용 조건만 즉시 해제한다. 나머지 적용 조건과 다른 입력 초안을 보존하고, 미제출 초안을 함께 적용하지 않는다.
- 상세 조건 버튼은 적용 중인 상세 조건의 수를 표시한다. 최소·최대 한 쌍은 한 조건으로 센다. 접어도 조건 요약과 해제가 가능해야 한다.
- '조회를 눌러 적용' 안내는 초안과 적용 조건이 다를 때만 표시한다. 원래 값으로 돌리면 지운다.
- 정렬·페이지·표시 개수 변경은 마지막 적용 조건을 쓴다. 날짜·상태만 즉시 조회하는 혼합 동작을 만들지 않는다.

## 4. 오류와 복원

- 직접 입력한 오류는 조회를 막고 기존 결과를 유지한다. 해당 필드에 오류를 연결하고 첫 오류 입력으로 포커스를 옮긴다.
- URL 복원 오류는 잘못된 조건만 화면 기본값으로 복구한다. 날짜 오류는 기간 묶음, 최소/최대 역전은 범위 묶음만 복구하고 검색어·상태 등 나머지는 보존한다.
- 복구한 조건을 구체적으로 알리고 정규화한 URL을 replace로 기록한다. 잘못된 정렬 값도 같은 절차로 처리한다.
- 사용자 조회·초기화·칩 해제·명시적인 바로조회·정렬 변경은 복원 가능한 이력으로 남긴다. 동일 URL이면 중복 이력을 만들지 않는다.
- URL 직접 진입·새로고침·뒤로·앞으로·상세 복귀에서 입력과 적용 결과가 일치한다. 화면이 관리하지 않는 쿼리와 고정 범위는 보존한다.
- 로딩/0건/오류/권한 없음/데이터 자체 없음은 구분한다. 0건에서 기간 확대를 제안할 수 있지만 사용자의 실행 없이 확대하지 않는다.

## 5. 데이터와 완료

- 검색·날짜·권한·소유자 조건을 서버에서 적용한 뒤 집계·정렬·페이지네이션한다. 현재 페이지 데이터만 검색하지 않는다.
- 결과·전체 건수·집계·URL은 같은 적용 조건을 설명해야 한다. 누적 수와 기간 내 수를 구분한다.
- 원천 필드가 있는지, 계산 가능한지, 기록 보강이 필요한지 구분한다. 없는 데이터로 가짜 필터·숫자를 만들지 않는다.
- 이전 응답이 최신 결과를 덮지 않게 한다. 조건 변경 시 오래된 행 선택이 다른 업무 조치에 쓰이지 않게 한다.
- 키보드·보이는 라벨·오류 연결·결과 갱신 안내·모바일 날짜 배치를 확인한다.
- PAGES.md에 화면별 기본값·조건 계약·실제 원천·검증 결과를 기록한다. 문서 작성/샘플 동작/API 검증/실서비스 반영은 별도로 보고한다.
- 저장 검색·개인화 열·조건별 분포·고급 검색 문법은 필요할 때 선택한다. 이 문서를 이유로 매 화면에 모든 기능을 추가하지 않는다.
