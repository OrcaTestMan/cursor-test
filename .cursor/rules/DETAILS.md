# 필터 상세 기준

공통 정책은 FILTERS.md, 프로젝트별 선택과 원천은 PAGES.md가 기준이다. 현재 작업에 해당하는 절만 읽는다.

## 1. 검색·숫자 입력

- 단어 AND·필드 OR를 기본으로 하고 SQL 조건에서도 같은 괄호 구조를 쓴다. 식별 번호 정확 일치를 일반 부분 검색과 구분한다.
- 앞뒤 공백·빈 검색·영문 대소문자·한글 조합·특수문자·길이 제한을 UI와 서버에서 맞춘다.
- LIKE의 %, _, 역슬래시를 리터럴로 찾을지 명세한다. 정규식·초성·오타 보정·따옴표 검색은 구현한 경우에만 안내한다.
- 숫자는 빈값·0·null을 구분한다. 정수 여부, 음수, 유한성, 정밀도와 실제 서버 상한, 최소≤최대를 검증한다.
- number 입력의 min/step만으로 검증을 대신하지 않는다. badInput 상태를 빈값으로 해석해 조건을 없애지 않는다.
- 공개 화면에서 관리자 전용 필드를 검색 대상으로 추가하지 않는다. 원문에만 일치하면 허용된 짧은 문맥을 제공할 수 있다.

## 2. 날짜

- ISO 날짜 형식과 실제 달력 날짜를 함께 검사한다. 2026-02-30은 오류, 2028-02-29는 유효, 2026-02-29는 오류다.
- 사용자 입력 오류는 조회를 막는다. URL의 잘못된 직접 지정 날짜는 날짜 묶음만 오늘로 복구한다. 검색어·상태를 전부 지우지 않는다.
- 날짜 미입력으로 전체기간을 추론하지 않는다. 전체기간은 별도 모드이고, 상대 기간 URL은 모드를 저장해 조회 시 재계산한다.
- 화면을 열어 둔 채 자정이 지나도 조회 시 새 날짜를 쓴다. 직접 지정 날짜는 고정한다. 수정 중인 초안은 자동으로 덮어쓰지 않는다.
- 시작 포함·종료 다음 날 제외, 프로젝트 시간대, 월말·연말·윤일·일광절약시간 적용 지역의 하루 경계를 고려한다.
- 로그인 기록 없음과 최근 N일 미활동은 다르다. 기록되지 않은 시각을 가입일/수정일/현재 시각으로 채우지 않는다.
- 작업 대기열을 임의로 전체기간 기본값으로 바꾸지 않는다. 필요한 바로조회는 '전체기간 미처리'처럼 범위를 이름에 표시한다.

## 3. 선택지·연결 조건

- 짧은 업무 선택지는 일반 선택칸, 긴 목록은 검색·선택값 제거·필요한 추가 로딩을 제공한다.
- 같은 필터 복수 선택 OR, 다른 필터 AND. 전체와 개별 값을 중복 저장하지 않는다.
- 부모 변경으로 무효해진 자식만 해제하고 이유를 알린다. 고정 조직·게시판 범위는 유지한다.
- 조건별 건수가 필요하면 자기 조건 제외 여부·다른 조건 반영 여부를 명세한다. 로딩·미집계를 0으로 표시하지 않는다.
- 선택한 0건 옵션도 해제할 수 있게 둔다. 결과가 없다는 이유로 다른 선택값으로 바꾸지 않는다.

## 5. 초안·적용·복원

- 검색창 ×는 초안만 지운다. 칩 ×는 해당 적용 조건만 즉시 해제한다. 전체 초기화는 기본값으로 즉시 조회한다.
- 칩 해제와 정렬은 미제출 초안을 함께 조회하지 않는다. 다른 초안은 유지하고 변경 안내를 보여 준다.
- 상세 조건 개수는 적용된 상세 속성 그룹 수다. 최소/최대 범위는 1개, 기본 기간은 상세 조건 수에서 제외한다.
- 인라인 상세 영역은 펼침/접힘이다. 대화상자 형태를 쓰면 적용/취소를 명확히 하고 취소가 결과를 바꾸지 않게 한다.
- URL은 허용된 조건·정렬·페이지를 검증한다. 잘못된 enum은 해당 기본값, 잘못된 범위는 범위 묶음만 복구한다.
- 복구 이유를 '가입일을 오늘로 변경', '정렬을 기본값으로 변경'처럼 구체적으로 표시하고 URL을 replace한다.
- 이 화면이 관리하지 않는 쿼리와 해시는 보존한다. 사용자 의도에 따른 변경은 push, 같은 URL은 중복 기록하지 않는다.
- 저장 검색을 제공하면 사용자·화면별로 분리하고 상대/고정 기간을 구분한다. 과거 저장 조건을 기본값으로 몰래 쓰지 않는다.

## 6. 결과·업무 조치

- 전체 결과·현재 표시 범위·그룹 수·원천 건수를 구분한다. 필터와 정렬을 판단할 수 있는 결과 열을 제공한다.
- 정렬은 기준·방향·동률 순서를 고정한다. 정확 검색 우선 규칙이 사용자가 선택한 정렬을 몰래 덮지 않는다.
- 0건에서 명시적인 기간 확대·조건 해제를 제공할 수 있다. 확대 후 건수를 조회하기 전에는 지어내지 않는다.
- 필터 조회와 삭제·차단·발송 등 업무 조치를 분리한다. 기존 일괄 조치에서는 현재 페이지/전체 결과/제외 항목/실제 대상 번호를 구분한다.
- 조건 변경으로 오래된 선택이 다른 대상에 적용되지 않게 한다. 업무 상태 변경 후 행·건수·페이지를 갱신한다.

## 7. 서버·성능

- UI→API→DTO→쿼리→목록/total/집계의 조건 계약을 연결한다. UI와 서버의 허용 enum·범위·단위를 맞춘다.
- 권한·소유자·경로의 고정 범위는 서버에서 강제한다. 정렬 키는 허용 목록으로 제한한다.
- 조건 적용 후 정렬·페이지네이션·집계한다. 일대다 JOIN 중복, 그룹 전/후 조건 적용 차이를 확인한다.
- 캐시 키에 모든 적용 조건을 포함하고 이전 응답을 취소하거나 순서를 보장한다. 재시도 시 초안을 잃지 않는다.
- 참조 옵션 API와 목록 API의 목적을 구분한다. 목록의 오늘 기본값이 수신자·옵션 조회를 누락시키지 않게 한다.
- 실제 데이터 규모와 실행 계획에 맞춰 인덱스·커서·검색 엔진 필요성을 판단한다. 이유 없이 별도 인프라를 추가하지 않는다.
- 원천 없음·집계 가능·새 기록 필요를 구분한다. 기록 보강·마이그레이션·호환 파라미터가 필요하면 남긴다.

## 8. 접근성·반응형

- 보이는 라벨과 실제 입력을 연결한다. 날짜 기준/시작/종료, 숫자 범위 최소/최대의 의미를 색·placeholder에만 맡기지 않는다.
- 오류가 난 필드에 aria-invalid와 오류 설명을 연결하고 첫 오류로 포커스를 옮긴다. 정상화하면 오래된 오류 상태를 지운다.
- 키보드 순서·IME·달력·선택지·상세 패널·닫은 뒤 포커스 복귀를 확인한다. 인라인 영역에 불필요한 포커스 가두기를 넣지 않는다.
- 결과 갱신과 URL 조건 복구를 읽기 도구에 알린다. 작은 보조 글자도 배경과 충분한 대비를 확보한다.
- 작은 화면에서 날짜 두 칸의 실제 값을 읽을 수 있어야 한다. 날짜 그룹은 나란히 두고 그룹 밖 입력이 다음 줄로 이동하게 한다.

## 9. 검증 범위

변경한 동작과 관련된 시나리오를 실행한다. 문구·색상만 바꾸고 모든 API 시험을 반복할 필요는 없다.

| 변경 영역 | 의미 있는 검증 |
| --- | --- |
| 기본값·날짜 | 첫 입력/요청/결과 일치, 윤일·없는 날짜·역전·자정·전체기간 |
| 검색·숫자 | 단어 AND/필드 OR, 번호 정확 일치, 0/빈값/음수/소수/역전/잘못된 숫자 |
| 적용·해제 | 조회 전 결과 유지, 검색어 ×, 칩 ×, 다른 초안 보존, 기본값 초기화 |
| URL·이력 | 잘못된 날짜·숫자·정렬·옵션의 부분 복구, 새로고침·뒤로·앞으로, 다른 쿼리 보존 |
| API·데이터 | 권한·소유자, 목록/total/집계 일치, 페이지 전체 검색, 이전 응답 순서 |
| 화면·오류 | PC·작은 모바일·키보드, 오류 포커스/설명, 상세 조건 개수 |

실행한 결과를 PAGES.md에 기록하고 미실행 항목은 미검증으로 남긴다. 문서·샘플·실제 서비스의 완료 상태를 구분한다.
